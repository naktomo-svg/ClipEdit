# ClipEdit セキュリティ監査の計画（2回目、2026-10-18）

前回の監査（`docs/security-audit-2026-10-15.md`、対象 `d4f9744`）のあと、58 コミットで src が約 1,400 行増えた（追加 1,575 行・削除 153 行）。unsafe は 46 → 72 ブロック。前回の指摘 S1〜S8 は対応済み（S8 は対応せず）。この計画は、増えたところと、前回は見ていない見方を確かめる。

## 1. 前提（脅威モデル）

- ネットワーク通信なし。ログイン中のユーザーの権限（asInvoker、中の整合性レベル）で常駐する。
- **配布する前提で評価する。** `make-dist.ps1` で zip を作るようになったので、前回「配布するなら」と書いた観点を本筋に入れる。
- 攻撃する側として考えるもの：
  1. 同じデスクトップにいる、**整合性レベルの低い**プロセス（ブラウザのサンドボックスなど）
  2. exe・config.toml を置いたフォルダに書き込めるもの
  3. 配布の途中で zip を差し替えるもの
  4. クリップボードに細工した内容を置くアプリ
- 同じユーザー・同じ整合性レベルで動くアプリは、もともとクリップボードもプロセスのメモリも読めるので、それによる指摘は「情報」に留める（前回と同じ扱い）。

## 2. 前回のあとで増えた・変わった攻撃面

| 場所 | 変わったこと | 見る理由 |
|---|---|---|
| `instance.rs` | 2回目の起動が、クラス名 `ClipEditMain` で窓を探し、そのプロセスに `AllowSetForegroundWindow` を渡し、`WM_OPEN_REQUEST` を送る。見つからなければ約2秒探し直し、メッセージボックスを出す（D1・D37・D41） | 同じクラス名の窓を先に作った偽物に、前面に出る権利と合図を渡してしまうか |
| `main.rs` の本体ウィンドウ | `TaskbarCreated` を受けるため、`HWND_MESSAGE` ではない普通のトップレベルの窓にした。`WM_COMMAND` で開く・自動起動の切り替え・設定の読み直し・終了を受ける | ほかのプロセスが `PostMessage` で自動起動のレジストリを書き換えたり、終了させたりできるか。整合性レベルの低いプロセスから届くか（UIPI） |
| `clipboard.rs` | 「残さない」印を読む `read_dword`、印を本文より先に置く書き込み（S1・D4・D17） | 細工した大きさのデータ、4 バイトより短い DWORD、ロックできないメモリ |
| `hotkey.rs` | 2つの ID で切り替える `switch`（D36）、`Display`（D42） | 登録が残ったままになる・外れる経路がないか |
| `config.rs` | toml のエラー文から行番号を作る（D35） | 細工した config.toml で落ちないか |
| `tray.rs` | 埋め込んだ .ico から大きさに合う画像を選ぶ（`pick_icon_image`）、通知の種類（D34） | 解析の境界。通知にクリップボードの中身が出ないか |
| `build.rs` | .ico から .res を自前で作る | ビルドで入力を信用しすぎていないか（入力は自分のリポジトリのファイル） |
| `.github/workflows/ci.yml` | GitHub Actions（Action はハッシュで固定、`permissions: contents: read`） | サプライチェーン：Action の固定・権限・フォークからのプルリクエスト |
| `tools/make-dist.ps1`・`make-notices.ps1` | 配布用 zip と SHA256、ライセンス文 | 配布物の完全性（署名がない） |

## 3. 監査の項目

それぞれ「何をするか」と「合格の条件」。見つけたものは S9 からの番号で記録する。

### A. コードを読む

| No | 内容 | 合格の条件 |
|---|---|---|
| A1 | **unsafe の全件レビュー（72 ブロック）**。前回のあとで増えた 26 ブロックは1つずつ、SAFETY コメントが実際のコードと合っているかまで見る。特に `read_dword` の境界、`WM_DPICHANGED` の lparam、`GetIconInfo` のビットマップの解放、`forward_with_retries` のクロージャの中の呼び出し | 境界の誤り・解放漏れ・二重解放・寿命の誤りがない。SAFETY の説明と実際が食い違わない |
| A2 | **本体ウィンドウと編集ウィンドウが受けるメッセージの一覧**を作り、ほかのプロセスから送られたら何が起きるかを1つずつ書く（`WM_COMMAND` の各 `CMD_*`、`WM_TRAY`、`WM_OPEN_REQUEST`、`WM_HOTKEY`、`TaskbarCreated`、`WM_SETTEXT` で編集欄を書き換えてからの Ctrl+Enter など） | 中身を漏らす・書き換える経路がない。あれば、同じユーザーにしかできないか（情報）、整合性レベルの低いプロセスにもできるか（指摘）を分ける |
| A3 | **パスワードの扱いの流れ**：「残さない」印の付いたテキストが、読み込み → 編集 → 書き込み → 隠す、のどこでコピーされ、どこに残るか（`String`、`Vec<u16>`、`GlobalAlloc`、編集欄、元に戻すのバッファ） | 閉じたあとに画面部品に残らない（S3 の回帰がない）。プロセスのヒープに残る分は「情報」として記録する |
| A4 | **通知・タイトル・メッセージボックスに出す文字列**をすべて洗い出す | クリップボードの中身が出ない。config.toml の中身は、行番号と toml の短い説明だけ |
| A5 | **パニックと異常終了**：`expect`・`unwrap`・配列の添字が、外から来るデータで落ちないか。`extern "system"` の関数の中でパニックしたときの動き | 外からのデータで落ちる経路がない |

### B. 実機で試す（スクリプトは scratchpad に置き、報告に場所を書く）

| No | 内容 | 合格の条件 |
|---|---|---|
| B1 | **整合性レベルの低いプロセスから**、本体ウィンドウに `WM_COMMAND`（自動起動の切り替え・終了）と `WM_OPEN_REQUEST`、編集ウィンドウに `WM_SETTEXT` / `WM_GETTEXT` を送る。低いプロセスは、PowerShell の複製に `icacls /setintegritylevel low` を付けて作る | どれも届かない（UIPI で止まる）。届くものがあれば指摘 |
| B2 | **同じユーザーのプロセスから**、B1 と同じものを送る | 結果を記録する（情報） |
| B3 | **偽の本体ウィンドウ**：クラス名 `ClipEditMain` の窓を先に作ってから ClipEdit を2回起動する | 偽物に何が渡るかを記録する。自動起動を偽物に乗っ取られないか |
| B4 | **細工したクリップボード**：終端の 0 がない `CF_UNICODETEXT`、0 バイト、奇数バイト、100MB、壊れた UTF-16（片方だけのサロゲート）、2 バイトの `CanIncludeInClipboardHistory`、ロックできないハンドル | 落ちない・固まらない。100MB で使うメモリと時間を記録する |
| B5 | **S1〜S7 の回帰**：前回の `dyn.ps1`・`residue.ps1` の手順をもう一度流す（印が残る、偽の `vcruntime140.dll` を読まない、閉じたあとに残らない、64KB を超える config.toml を読まない） | 前回の対応のとおり |
| B6 | **DLL の読み込み**：Process Monitor か `SetDllDirectory` の確認で、exe と同じフォルダから DLL を探しに行かないか（静的リンクのあとで、ほかに探す DLL がないか） | exe のフォルダで見つからなかった DLL を、あとから読む経路がない |
| B7 | **プロセスのメモリ**：パスワードを開いて閉じたあと、ダンプを取って文字列を探す | 結果を記録する（情報。同じユーザーはもともと読める） |

### C. 自動の検査

| No | 内容 | 合格の条件 |
|---|---|---|
| C1 | `cargo audit`・`cargo deny check`（`debt-scan.ps1` でも流れる） | 既知の脆弱性 0、FAILED 0 |
| C2 | `check-release.ps1`（静的リンク・CFG・ASLR・DEP・ユーザー名のパス・マニフェスト・アイコン）。あわせて `dumpbin /headers` で、高エントロピー ASLR と、マニフェストの `asInvoker` を確かめる | すべて ok |
| C3 | **ランダム入力（proptest）**：前回の 12 種類に、増えた純粋な関数を足す。`describe_error`（細工した TOML）、`copy_wide`（サロゲートの境界）、`HotKey` の表示と解析の往復、`hotkey::switch`（登録の成否の組み合わせ）、`find_with_retries`、`pick_icon_image`（細工した .ico） | パニックしない。往復などの性質が成り立つ |
| C4 | clippy pedantic と `clippy::undocumented_unsafe_blocks` | 不具合につながる警告がない |

### D. 配布とサプライチェーン

| No | 内容 | 合格の条件 |
|---|---|---|
| D1 | `ci.yml`：Action がハッシュで固定されているか、トークンの権限、`persist-credentials: false`、フォークからのプルリクエストで秘密の情報に触れないか、キャッシュ（rust-cache）の汚染 | 書き込み権限のある経路がない |
| D2 | 配布用 zip：中身（exe・README・config.example.toml・LICENSE・THIRD-PARTY-NOTICES.txt）だけか、ユーザー名やビルドした PC のパスが入っていないか | 余計なものが入っていない |
| D3 | **署名と完全性**：exe と zip に署名がない。利用者が本物か確かめる手段（SHA256 をどこで公開するか）を決める | 方針を決めて報告に書く（判断は利用者） |
| D4 | 配布用 README の置き場所の注意（「ダウンロード」フォルダに置かない）と、自動起動の Run キーが置き場所のパスを指すこと | 説明がコードの動きと合っている |

## 4. 進め方

1. **準備**：`git diff d4f9744..HEAD` を読み、A2 のメッセージの一覧を作る。前回の `dyn.ps1`・`residue.ps1`・`fuzzprobe` を scratchpad に作り直す（前回の scratchpad は残っていない）
2. **コードを読む**（A1〜A5）
3. **実機で試す**（B1〜B7）。ClipEdit を止めて、クリップボードを書き換えることを先に知らせる
4. **自動の検査**（C1〜C4）
5. **配布とサプライチェーン**（D1〜D4）
6. **報告**：`docs/security-audit-2026-10-XX.md` に、前回と同じ形（指摘一覧・各指摘・問題なしだった項目・推奨する修正順・検査に使ったもの）で書く
7. **修正は報告のあとで、利用者が決めてから**行う。前回と同じく、指摘ごとに1コミット、テストを先に書く

コードは監査の間は変えない。見つけたものは、重要度（高・中・低・情報）と、自分専用の場合と配布する場合で重要度が変わるかを書く。

## 5. 範囲に入れないもの

- 管理者権限の攻撃者、カーネル、物理的に PC に触れる攻撃者
- Windows 自体（クリップボード履歴・クラウド同期）の不具合
- 依存ライブラリのソースそのものの監査（`cargo audit` / `cargo deny` の結果と、版の固定を見るだけ）

## 6. 決めたこと（2026-10-18、利用者）

1. **配布する前提で評価する。**
2. **署名（D3）を範囲に入れる。** 証明書の入手（有料）や Microsoft Store を含めた選択肢まで調べ、報告に比較を書く
3. **B1 は、PowerShell の複製に低い整合性レベルを付けて動かす。** PC の設定は変えず、複製は終わったら消す
