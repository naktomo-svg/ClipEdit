# ClipEdit

クリップボードのテキストを、ショートカットキーひとつで開いて編集できる Windows 用の常駐アプリです。
編集後に Ctrl+Enter を押すとクリップボードに書き戻されるので、あとは貼り付けたい場所で Ctrl+V を押します。

- タスクトレイに常駐し、ホットキー（既定は **Ctrl+Alt+V**）ですぐ開く（もう一度 exe を起動しても、動いているほうの編集ウィンドウが開きます）
- Rust と Win32 API だけで作った約 600KB の exe 1つ（インストール不要、ランタイム不要）
- ネットワーク通信なし、ログ出力なし

## 使い方

1. `clipedit.exe` を自分で書き込めるフォルダに置いて起動すると、タスクトレイにアイコンが出ます（`C:\Program Files` には置かないでください。理由は下の「お気に入り」を参照）。
   Windows 11 では最初は「^」の中に入っているので、タスクバーへドラッグすると常に表示されます。
2. テキストをコピーしてから **Ctrl+Alt+V** を押すと、マウスカーソルのある画面の中央に編集ウィンドウが開きます。
3. 編集して **Ctrl+Enter** を押すと、クリップボードが書き換わってウィンドウが閉じます。
4. 貼り付けたい場所で **Ctrl+V** を押します。

| キー | 動作 |
|---|---|
| Ctrl+Enter | クリップボードに書き込んで閉じる |
| Esc / × ボタン | 書き込まずに閉じる |
| Ctrl+A | すべて選択 |
| Ctrl+Backspace | 直前の1語を消す（日本語はひらがな・カタカナ・漢字の区切りで消える） |
| Ctrl+Z | 元に戻す |
| Ctrl+1〜Ctrl+9 | お気に入りの 1〜9 番目に入れ替える。直前の1回だけ Ctrl+Z で戻せる（「残さない」印つきの内容から入れ替えたときや、長い行のお気に入りのときは戻せない）。AltGr（Ctrl+Alt）+ 数字は、お気に入りの呼び出しとして扱わない |
| Alt+F | メニューバーの「お気に入り」を開く |

- 開いている間にもう一度ホットキーを押しても、編集中の内容は消えません（前面に出るだけ）。
- クリップボードが画像などテキスト以外のときは、空の状態で開き、タイトルに「(テキストなし)」と出ます。
- 改行はすべて CRLF にそろえて表示・書き込みします。
- 5,000 文字を超える長い行（改行のない JSON や Base64 など）があるときは、折り返さずに横スクロールで表示し、タイトルに「(長い行があるため折り返さずに表示)」と出ます（折り返すと開くのに何十秒もかかるため）。
- クリップボードに書き込めなかったとき（ほかのアプリが開いたままにしているときなど）は、ウィンドウを閉じずに、タイトルに「書き込み失敗」と理由が出ます。編集欄の中のコピー・切り取りも同じで、タイトルに「コピー失敗」「切り取り失敗」と出ます（切り取ったところは消えません。次に成功すると元のタイトルに戻ります）。

### トレイアイコン

- 左クリック: 編集ウィンドウを開く
- 右クリック: メニュー
  - **開く**
  - **お気に入り**: お気に入りの一覧（サブメニュー）。選ぶと、そのお気に入りを入れた状態で編集ウィンドウが開きます（クリップボードは読みません）。末尾の「お気に入りを整理…」でフォルダを開きます
  - **ログイン時に起動**: チェックすると Windows へのサインイン時に自動で起動します（`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` に登録）。exe を移動したときはチェックが外れ、「ログイン時に起動（別の場所の exe が登録されています）」と出ます。もう一度選ぶと新しい場所で登録し直します（登録を消したいときは、そのあともう一度選んでチェックを外します）。
  - **設定を読み直す**: `config.toml` を読み直し、ホットキーを登録し直します（書き方が違う・新しいキーがほかのアプリに使われているときは、それまでのホットキーをそのまま使います）
  - **終了**

### お気に入り

よく使うプロンプトを保存しておき、編集ウィンドウに呼び出せます。呼び出すと、編集欄の中身がまるごとそのお気に入りに入れ替わります。手直しはその回だけのもので、Ctrl+Enter で送っても保存してあるお気に入りは変わりません。

- 保存場所: `clipedit.exe` と同じフォルダの `favorites` フォルダ。1つのお気に入りが1つの `.txt` ファイルです（暗号化はしません。ふつうのテキストファイルです）
  - 配布用 zip の `favorites` フォルダには、見本のプロンプトが8本入っています（元は `assets/favorites/`）。新しい版に入れ替えるときは `clipedit.exe` だけを上書きしないと、書き換えた見本が元に戻ります
  - そのため `clipedit.exe` は、自分で書き込めるフォルダ（例: `C:\Users\<ユーザー名>\Apps\ClipEdit\`）に置いてください。「ダウンロード」フォルダは書き込めますが、ストレージ センサーの設定によってしばらく開いていないファイルが自動で削除され、exe やお気に入りが消えることがあるので避けます。`C:\Program Files` は、ふつうに起動したアプリからは書き込めない（「管理者として実行」したときだけ書ける）ので、「お気に入りに追加」が失敗します。`favorites` フォルダがないときは、フォルダを作れずに「お気に入りを整理…」も失敗します。置き場所を移したら、「ログイン時に起動」はトレイのメニューでもう一度選び直します
- ファイル名: `<番号> <名前>.txt`（例: `01 コードレビュー依頼.txt`）。一覧には番号と `.txt` を除いた名前が出て、番号の小さい順（同じ番号なら名前順）に並びます。番号のないファイルは、番号つきのものの後ろに並びます
- 呼び出す番号は、一覧での位置（上から 1, 2, 3, …）です。ファイル名の番号そのものではありません（`01` と `05` だけなら、`05` は Ctrl+2）
- 書き直し・名前の変更・並べ替え・削除は、メモ帳とエクスプローラーで行います。メニューを出すたびにフォルダを読み直すので、直した内容は次にメニューを出したときから反映されます
- 上限は 20 本、1 ファイル 64KB までです。超えたもの、UTF-8 でないもの（UTF-16 など）は一覧に出ず、メニューに「読み込めないファイルが N 個あります」「上限の 20 本を超えた N 個は出していません」と出ます。一覧を作るときに中身を読むのは 100 個まで（20 本そろったら、残りは読まずに数えるだけ）なので、読み込めないファイルがたくさんあると、その先のお気に入りは出ません（その分も「読み込めない」に数えます）。メモ帳では UTF-8 で保存してください
- サブフォルダと、`.txt` 以外のファイルは無視します

編集ウィンドウでの使い方:

- **Ctrl+1〜Ctrl+9**（テンキーも可）: 一覧の 1〜9 番目に入れ替えます。その番号がなければ何もしません。入れ替えたあとはカーソルが先頭に来ます
- **メニューバーの「お気に入り」**（Alt+F。Alt を押して離してから F でも開きます）: 一覧と次の項目が出ます。1〜9 番目は、メニューが出ている間に数字キーを押しても選べます。開くたびにフォルダを読み直します
  - **今の内容をお気に入りに追加**: 編集欄の今の内容を、新しいファイルとして保存します。ファイル名は本文の最初の空でない行（30 文字まで。ファイル名に使えない文字は `_` になります）から作り、番号は今ある最大の番号の次になります。同じ名前があれば ` (2)` などを付け、既存のファイルは上書きしません。保存すると、トレイの通知でお知らせします
  - **お気に入りを整理…**: `favorites` フォルダをエクスプローラーで開きます（フォルダがなければ作ります）
- 追加できないとき（空の内容、すでに 20 本ある、64KB を超える、書き込めない）は、理由を通知します。パスワード管理ソフトなどが「履歴・クラウドに残さない」印を付けてコピーした内容は、お気に入りに追加できません（そうした内容を編集欄に貼り付けたときも同じです）

日本語を変換している途中（未確定の文字があるとき）は、Ctrl+数字は IME に渡るので効きません。確定してから押すか、メニューバーの「お気に入り」かトレイのメニューの「お気に入り」から呼び出します。Ctrl+Space は、IME の設定でオン／オフに割り当てられていることがあり、そのときは ClipEdit に届かないので使いません。

## 設定

`config.example.toml` を `config.toml` という名前で `clipedit.exe` と同じフォルダに置くと、ホットキーを変えられます。
UTF-8 で保存してください。変更は、トレイのメニューの「設定を読み直す」を選ぶと反映されます（起動し直しても反映されます）。

```toml
hotkey = "Ctrl+Shift+E"
```

- 修飾キー: `Ctrl` / `Alt` / `Shift` / `Win`（1つ以上必要、大文字小文字は区別しない）
- キー: `A`〜`Z`、`0`〜`9`、`F1`〜`F24`、`Space`、`Insert`

ファイルが読めない・書き方が違う・64KB を超える、といった場合は既定値（Ctrl+Alt+V）で起動し、トレイから通知で知らせます。
ホットキーがほかのアプリに使われているときは、ホットキーなしで起動して通知を出します。その間もトレイのアイコンから開けます。

ホットキーを Ctrl+1〜9 にすると、ほかのアプリと同じく編集ウィンドウにもそのキーが届かなくなるので、編集ウィンドウでのお気に入りの呼び出しには使えなくなります（トレイのメニューからは呼べます）。

## セキュリティとプライバシー

- パスワード管理ソフトなどが「クリップボード履歴・クラウドに残さない」印を付けてコピーしたテキストは、書き戻すときにも同じ印を付け直します。編集欄の中でコピー・切り取りしたとき（Ctrl+C・Ctrl+X・右クリックのメニュー）も同じです。印の付いたものを貼り付けると、書き戻すときに印を付けます。ClipEdit を通しても Win+V の履歴やクラウド同期に残りません。
- ウィンドウを閉じると、編集欄の内容と「元に戻す」の履歴を消します。
- ClipEdit がファイルを書くのは、「お気に入りに追加」を選んだときの `favorites` フォルダのファイルだけです（暗号化はしません。フォルダがなければ、追加と「お気に入りを整理…」のときに作ります）。ほかに書くのは、「ログイン時に起動」をオンにしたときのレジストリの値だけです。「残さない」印つきの内容は追加できません。
- C ランタイムを静的リンクしているので、exe と同じフォルダに置かれた DLL を読み込みません。
- セキュリティ監査を行い、見つかった問題は直すか、影響の小さいものとして記録しています。監査の報告書は開発用の非公開リポジトリ（`docs/security-audit-*.md`）だけに置いています。

## ビルド

必要なもの: Rust（stable、2024 edition）、Visual Studio の C++ ビルドツール（MSVC）

```powershell
# 配布用（ユーザー名などビルドした PC のパスを exe から除き、保護設定を検査する）
pwsh -NoProfile -File tools/build-release.ps1

# 開発用
cargo build --release
```

できた exe は `target\release\clipedit.exe` です。
ClipEdit が起動していると exe を上書きできないので、ビルド前にトレイの「終了」で止めてください。

`.cargo/config.toml` で C ランタイムの静的リンクと Control Flow Guard を有効にしています。
`tools/check-release.ps1` は、ビルドした exe がこれらの設定を満たすかを確かめます。

## テスト

```powershell
cargo test                                   # 通常のテスト
cargo test -- --ignored --test-threads=1     # 実際のクリップボード・ウィンドウ・レジストリを使うテスト
cargo clippy --all-targets                   # unsafe ブロックには SAFETY コメントが必須
```

まとめて流すときは `pwsh -NoProfile -File tools/check-all.ps1` を使います（書式・clippy・テスト・負債の検査・ライセンス文の書き出し）。
`-Hardware` を付けると、実機を使うテストと配布用ビルドの検査も流します。

GitHub に push するかプルリクエストを出すと、GitHub Actions（`.github/workflows/ci.yml`）が `check-all.ps1` と配布用ビルドの検査を流します。実機を使うテストは CI では流さないので、手元で `-Hardware` を付けて流してください。

配布するときは、`CHANGELOG.md` の「未公開」を版と日付に書き換え、`Cargo.toml` の `version` を上げてコミットし、同じ版のタグ（例: `v0.2.0`）を push します。`.github/workflows/release.yml` が検査・ビルドをして、zip とチェックサムを GitHub Release に上げます（タグと `Cargo.toml` の版が違うと止まります）。

開発は非公開のリポジトリ `naktomo-svg/ClipEdit-dev` で行います。配布は、公開リポジトリ `naktomo-svg/ClipEdit` の Releases（https://github.com/naktomo-svg/ClipEdit/releases ）と note の記事に添付する zip です。公開リポジトリは 2026-10-18 に一度公開したあと非公開に戻し、2026-11-17 に v0.3.6 で公開し直しました。新しい版を出すときは、タグを付けたあとで `pwsh -NoProfile -File tools/publish-public.ps1` を実行し、差分を確かめてから `-Push` を付けて実行し直します（公開側には作業の履歴と作者のメールアドレスを出しません。設計・計画・監査報告・負債の台帳とその基準値は、`.gitattributes` の `export-ignore` で外します）。写し先のフォルダは、このスクリプトが作った複製で、変更・stash・push していないコミット（前回このスクリプトが作ったものを除く）がないときだけ作り直します。2026-10-20 より前の版のスクリプトで作った複製には目印がないので、一度だけ手で消してから実行します。公開リポジトリでは、タグの push で同じ `release.yml` が動き、attestation 付きの Release ができます。

`--ignored` のテストはクリップボードの中身を書き換えます（レジストリの自動起動設定はテスト後に元に戻します）。
